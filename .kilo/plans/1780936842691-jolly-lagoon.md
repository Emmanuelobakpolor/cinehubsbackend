# Responsive Layout & Mobile Behavior Analysis Plan

## Scope
Analyze **layout, components, breakpoints, and mobile UX** across:
- **cinehubsadmin** (TanStack Start + React + Tailwind v4 + shadcn/ui — the responsive web target)
- **cinehubs** (Flutter mobile app — native widgets, no CSS breakpoints; relevant for overlap patterns)

---

## Analysis Framework

### 1. Breakpoint Strategy
- Tailwind v4 breakpoints (implied from utilities): `sm` (640px), `md` (768px), `lg` (1024px), `xl` (1280px), `2xl` (1536px)
- Custom `min-[480px]` used in dashboard for early tablet breakpoint
- Mobile-first approach: base styles are mobile, `md:` overrides for desktop
- Document the **exact thresholds** used and patterns (`hidden md:flex`, `md:hidden`, `lg:grid-cols-4` etc.)

### 2. Section-by-Section Mobile Behavior
For each major page/layout:
- **Login**: split-panel (branding left, form right) → single column on mobile via `lg:hidden` / `lg:flex`
- **Sidebar**: fixed drawer on mobile (`translate-x-[-100%]`), collapsed icon-only on desktop (`md:w-[4.5rem]`)
- **Topbar**: hamburger on mobile, full search + user profile on desktop
- **Dashboard**: stat cards 1→2→4 cols, data tables → card stacks on mobile
- **Movies**: table rows hidden, mobile cards shown (`sm:hidden` / `sm:block` inverse)
- **Categories**: same table→card switch
- **Subscribers**: table→card switch + horizontal pill filters
- **Broadcast**: card grid 1→2→3→4 cols
- **Upload**: single column → 3-col stats grid
- **Modals**: createPortal with fixed overlay, max-w-md with `max-h-[85vh]` scroll

### 3. Visibility Switching
Catalog all `hidden md:flex`, `md:hidden`, `sm:block`, `lg:hidden` patterns
- Identify the intent behind each switch
- Note any inconsistency (e.g. `sm:hidden` vs `md:hidden` for table rows)

### 4. Layout Stacking (flex/grid)
- Stat grids: `grid-cols-1` → `min-[480px]:grid-cols-2` → `lg:grid-cols-4`
- Main content: `grid-cols-1` → `xl:grid-cols-[...]` sidebar/main split
- Modal footers: `flex-col-reverse` → `sm:flex-row`
- Mobile card stacking: full-width cards with `space-y-3`

### 5. Typography / Spacing Scaling
- Font sizes: `text-xs` → `text-sm` → `text-base` across breakpoints
- Spacing: `p-4` → `sm:p-6` → `md:p-8` progressive
- Tight mobile spacing vs generous desktop padding
- Title scaling (`text-xl` → `sm:text-2xl` → `lg:text-4xl`)

### 6. Button / Input Tap Usability
- Minimum hit targets: `h-9`, `h-10`, `h-11`, `py-3.5` for inputs
- Mobile action buttons: full-width (`w-full`) on small screens
- Icon buttons: `h-9 w-9` minimum, `h-10 w-10` for prominent actions
- Modal buttons: `py-3` with `active:scale-[0.98]` feedback

### 7. Overflow / Scroll Risks
- `overflow-x-hidden` on layout shell and main content
- `min-w-0` extensively on flex children to prevent flex overflow
- Modals: `max-h-[85vh] overflow-y-auto`
- Notification dropdown: `max-h-[65vh]` / `sm:max-h-[360px]`
- Sidebar nav: `overflow-y-auto` with `min-h-0`
- Potential risk: horizontal pill row `overflow-x-auto` without visible scrollbar indicator

### 8. Fixed / Sticky / Modal Behavior
- Sidebar: `fixed left-0 top-0 z-30 h-screen` with backdrop overlay on mobile
- Modals: `fixed inset-0 z-[9999]` via createPortal
- Topbar dropdowns: `absolute right-0 top-[calc(100%+8px)]`
- Drawer sheet pattern (vaul in package.json — imported but not deeply analyzed)
- `createPortal` used for AddMovieModal and BroadcastModal (portal to document.body)

### 9. Strengths
- Consistent tablet breakpoint (`min-[480px]`) for early landscape phones
- Explicit mobile card fallbacks instead of responsive table hacks
- `min-w-0` pattern prevents flex overflow blowouts
- `createPortal` for modals avoids z-index stacking context issues
- Focus ring styles (`:focus-visible` with `--color-ring`)
- Active/press feedback on buttons (`active:scale-95`, `active:scale-[0.98]`)

### 10. Weak Points
- **Inconsistent breakpoint usage**: some pages use `sm:` for mobile/desktop switch, others use `md:` (Movies uses `sm:hidden`/`sm:block`, Dashboard uses `md:hidden`/`md:block`)
- **No safe-area handling**: no `env(safe-area-inset-*)` for iOS notch/home indicator
- **No viewport meta lock**: likely missing `viewport-fit=cover` in HTML
- **Modal overflow**: `max-h-[85vh]` may still get clipped by mobile browser chrome on landscape
- **Search bar**: inline expansion on mobile is clever but input autoFocus may trigger zoom on iOS (font-size < 16px)
- **Sidebar collapse**: `md:w-[4.5rem]` hardcoded in Tailwind class — relies on sidebar `w-64` default matching `md:ml-64`
- **Horizontal pill overflow**: `overflow-x-auto` with `scrollbarWidth: none` — no touch-scroll affordance
- **No `prefers-reduced-motion` media query** despite heavy transitions/animations
- **Z-index stacking**: sidebar `z-30`, topbar `z-40`, modals `z-[9999]` — potential conflict if topbar dropdown overlaps collapsed sidebar on small screens

### 11. Exact Reusable Patterns
Document these as copy-paste templates:
- **StatCard**: grid-based card with icon circle, label, value, trend/link
- **TableToCardSwitch**: `hidden sm:block` table + `sm:hidden` card stack
- **MobileActionCard**: card with thumbnail, info, status badges, action buttons
- **ModalOverlay**: fixed inset-0 + bg-black/70 + click-outside-to-close + createPortal
- **SidebarShell**: fixed sidebar with backdrop, mobile drawer state, desktop collapse
- **TopbarShell**: responsive search (hidden mobile, visible desktop), notifications bell, user menu
- **PillFilter**: horizontal scroll row with active ring state
- **CardHeader**: `rounded-2xl bg-card px-4 py-4 sm:px-6` — page title + action button
- **EmptyState**: centered icon + heading + description + CTA button
- **SkeletonLoader**: animate-pulse bars matching real content layout
